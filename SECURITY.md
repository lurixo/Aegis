# Security Policy

Aegis is a keyboard — it can see everything a user types — so we take security and privacy reports
seriously. Thank you for helping keep users safe.

## Supported versions

Aegis is in active development and ships **pre-release / debug** builds. Only the **latest release**
receives security fixes; there are no long-term support branches yet.

| Version                | Supported |
| ---------------------- | --------- |
| Latest release         | ✅        |
| Any older pre-release  | ❌        |

## Reporting a vulnerability

**Please do not report security issues in public GitHub issues, pull requests, or discussions.**

Report privately using **GitHub's private vulnerability reporting**:

1. Go to the repository's **Security** tab.
2. Choose **Report a vulnerability**.
3. Describe the issue, its impact, and clear reproduction steps (device, Android version, and the
   input mode or panel involved, where relevant).

If private reporting is unavailable to you, contact the maintainer via their GitHub profile
([@lurixo](https://github.com/lurixo)) and ask for a private channel before sharing details.

## What to expect

- **Acknowledgment:** best effort, typically within about a week.
- **Updates:** we will keep you informed as we investigate and work on a fix.
- **Disclosure:** please give us reasonable time to release a fix before any public disclosure. We
  are happy to credit you once the issue is resolved, if you would like.

## Scope

In scope: the Aegis app and the dictionary/model assets it downloads. Because typing is fully
offline (see [PRIVACY.md](PRIVACY.md)), the most valuable reports concern local data handling,
permission use, and the integrity of downloaded assets.
